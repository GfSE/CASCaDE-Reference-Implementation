# Neo4j Export Plugin

## Overview
The Neo4j Export plugin lets users send generated Cypher statements directly to a Neo4j HTTP endpoint. It constructs the Cypher payload from packages, then posts statements in the correct order for schema and data application.

## Features

### 1. Direct Neo4j Export
- Reads packages from the `PackageCache` store
- Converts packages to Cypher using `getCypher()`
- Sends statements to the Neo4j HTTP transaction endpoint

### 2. Connection and Authentication
- Accepts Neo4j URI, username, password, and database name
- Normalizes `bolt://` and `neo4j://` URIs to HTTP endpoints
- Uses Basic authentication header

### 3. Statement Ordering
- Splits exported Cypher into individual statements
- Detects schema statements (`CREATE CONSTRAINT`, `CREATE INDEX`, etc.)
- Sends schema statements before data statements

### 4. Error Handling and Logging
- Returns detailed error info from Neo4j responses
- Logs statement counts and first statement previews
- Stops on first failed statement with an error message

## Usage

### User Workflow
1. Click **"Export Neo4j"**
2. Provide:
   - Neo4j URI (`bolt://localhost:7687` or `http://localhost:7474`)
   - Username
   - Password
   - Database name
3. Click **Export**
4. Plugin sends Cypher to the Neo4j server and reports success or failure

### Code Example
```typescript
import { PackageCache } from '../../../stores/package-cache';
import { getCypher } from '../../../common/export/cypher/getCypher';
import { exportToNeo4j } from './neo4j-export';

const cache = PackageCache();
const cypherText = cache.packages
  .map(pkg => getCypher(toRaw(pkg), { includeConstraints: true }))
  .join('\n\n');

const result = await exportToNeo4j(cypherText, {
  uri: 'bolt://localhost:7687',
  username: 'neo4j',
  password: 'password',
  database: 'neo4j'
});
```

## Implementation Details

### Dependencies
- **Pinia Store**: `PackageCache`
- **Export Utility**: `getCypher()` from `src/common/export/cypher/getCypher`
- **Neo4j helper**: `exportToNeo4j()` in `neo4j-export.ts`
- **Vue**: `vue-class-component`, `toRaw`
- **Helpers**: `LOG`

### Data Flow
1. `openDialog()` loads or refreshes the package cache
2. `exportPackages()` generates Cypher text for all packages
3. `exportToNeo4j()` normalizes the Neo4j URI and endpoint
4. Statements are split, schema statements are sent first
5. Each statement is posted to `/db/{database}/tx/commit`
6. Errors are returned with statement context

### HTTP Behavior
- Uses `fetch()` with JSON payload
- Sets `Content-Type: application/json`
- Encodes credentials with Base64
- Parses Neo4j error payloads when available

### URI Normalization
- Converts `bolt://` and `neo4j://` to `http://`
- Maps default Neo4j Bolt ports to HTTP ports if needed
- Strips trailing slashes from the endpoint

### Statement Parsing
- Supports single-quoted, double-quoted, and backticked strings
- Handles line comments (`//`) and block comments (`/* ... */`)
- Splits statements by semicolon outside of quoted contexts

## Current Limitations
- Does not support Neo4j driver or Bolt transport directly
- Uses HTTP transaction endpoint only
- Sends each statement sequentially, not in batch
- No retry or transaction rollback support
- Assumes Cypher generated by `getCypher()` is Neo4j-compatible

## Future Enhancements
- Add direct Bolt/Neo4j driver support
- Batch multiple statements in one transaction request
- Support explicit retry, rollback, or partial commit handling
- Add export options for statement grouping or skip constraints
- Improve compatibility with Neo4j 5+ REST endpoints
